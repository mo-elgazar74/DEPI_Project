# Hybrid Search: BM25 + embeddings

## Summary

Hybrid search combines traditional keyword-based BM25 search with modern semantic vector search to retrieve documents that match both exact keywords and conceptual meaning, providing more comprehensive results than either method alone.

## Key concepts

*   **BM25 (Best Matching 25)** is a classic keyword search algorithm that scores documents based on exact term matches, considering term frequency and document length; it's excellent for finding documents containing specific names, dates, or technical terms you type exactly.
    *   *Example: Searching for "photosynthesis" with BM25 will find all documents containing that exact word, much like using Ctrl+F in a document.*
*   **Embeddings** are numerical vector representations of text meaning generated by AI models; they capture semantic relationships so that similar concepts (like "car" and "automobile") have similar vectors even without word overlap.
    *   *Example: Using [[RagSystemRoadmap/EmbeddingHuggingfaceMultilingualE5Small.md]] to convert "How do plants make food?" into a 384-dimensional vector for [[RagSystemRoadmap/SemanticSearch.md]].*
*   **Hybrid fusion** is the technique of combining BM25 and embedding scores into a single ranked list, typically using weighted summation or reciprocal rank fusion (RRF), which balances precise keyword matching with conceptual understanding.
    *   *Example: Like a hiring manager who considers both specific qualifications on a resume (BM25) and overall cultural fit and potential (embeddings) when ranking candidates.*

## Why it matters

*   **Compensates for weaknesses** - BM25 fails with synonyms and paraphrases (searching "automobile" won't find "car" documents), while embeddings can miss precise technical terms; hybrid covers both scenarios.
    *   *Example: A query for "feline diseases" finds documents with "cat illnesses" (via embeddings) and precise mentions of "feline leukemia virus" (via BM25).*
*   **Improves recall and precision** by retrieving more relevant documents from different matching perspectives, which is crucial for educational systems where students might phrase questions differently than textbook language.
    *   *Example: In [[RagSystemRoadmap/Ali5ModeExplainLikeToA5YearOld.md]], students might ask "Why is sky blue?" while textbooks say "Rayleigh scattering explanation" - hybrid finds both.*
*   **Handles diverse query types** effectively, from specific fact lookups (BM25 excels) to broad conceptual questions (embeddings excel), making it ideal for [[RagSystemRoadmap/AskHandleQuestionAnswering.md]] where question styles vary widely.

## Core steps

*   **Run parallel searches** by executing both BM25 and vector search simultaneously against your document store, then normalize their scores to a common scale for fair comparison.
    *   *Reason: Both algorithms produce scores on different scales that can't be directly compared without normalization.*
    *   *Example: Using [[RagSystemRoadmap/AsyncSearchForSpeed.md]] to query both [[RagSystemRoadmap/DatabaseQdrant.md]] for vectors and Elasticsearch for BM25 concurrently.*
*   **Apply fusion algorithm** to combine the normalized scores, typically using weighted sum (assigning weights like 0.4 BM25 + 0.6 embeddings) or reciprocal rank fusion (which considers rank positions rather than raw scores).
    *   *Reason: Different fusion methods work better for different use cases - weighted sum preserves score magnitude while RRF is more robust to score distribution differences.*
    *   *Example:*
        ```python
        # Simple weighted sum fusion
        hybrid_score = (0.4 * normalized_bm25_score) + (0.6 * normalized_vector_score)
        ```
*   **Deduplicate and rerank** results by removing overlapping documents from the fused list and optionally applying a [[RagSystemRoadmap/OptionallyRerankResults.md|cross-encoder reranker]] to refine the final ordering based on deeper semantic understanding.
    *   *Reason: BM25 and vector search often retrieve similar documents, and reranking can improve final precision for [[RagSystemRoadmap/BuildUnifiedContext.md]].*
    *   *Example: Using a transformer model to re-evaluate the top 20 fused results by comparing each document directly to the query.*

## Checks

*   **Are you getting both keyword matches and semantic matches in your results?**
    *   ✔ Good: Query "neural network backpropagation" returns documents with exact term "backpropagation" AND documents about "gradient descent in AI systems"
    *   ✘ Poor: Only returns exact keyword matches or only conceptual matches
*   **Does changing query wording significantly affect result quality?**
    *   ✔ Good: "car maintenance" and "automobile upkeep" return similar high-quality results
    *   ✘ Poor: Results degrade completely when using synonyms or paraphrased queries
*   **Are technical terms and specific entities being found reliably?**
    *   ✔ Good: Query "Python list comprehension syntax" finds exact code examples containing those terms
    *   ✘ Poor: Technical terms get lost in semantic similarity, returning generic programming content instead

## Failure modes

*   **Poor score normalization** happens when BM25 and embedding scores have different distributions and ranges, causing one method to dominate the results regardless of weights.
    *   *Fix: Implement robust normalization like min-max scaling or z-score normalization based on score distributions from your test queries.*
*   **Suboptimal weight balancing** occurs when the BM25/embedding ratio doesn't match your use case, such as too much BM25 weight for conversational queries or too much embedding weight for exact term lookups.
    *   *Fix: Use [[RagSystemRoadmap/EvaluationLangfuseCustomScripts.md]] to test different weight combinations on diverse query types and optimize for your [[RagSystemRoadmap/RetrievalPrecisionKRecallK.md]] metrics.*
*   **Vocabulary mismatch** between queries and documents can undermine BM25, particularly with technical jargon or domain-specific terminology that doesn't appear in the source texts.
    *   *Fix: Expand queries with synonyms or use query expansion techniques, and consider [[RagSystemRoadmap/FineTunedEmbeddingsForArabicDomain.md|domain-tuned embeddings]] for specialized vocabulary.*

## Examples

*   **Library research analogy**: Imagine asking a librarian for books about "climate change impacts on agriculture." A traditional librarian (BM25) finds books with those exact words in the index. A modern librarian (embeddings) understands the concept and finds books about "global warming effects on farming." Hybrid search is like having both librarians work together, giving you the most comprehensive book selection.
*   **Technical implementation** showing how to combine results from Qdrant vector search with BM25 search:
    ```python
    def hybrid_search(query, vector_weight=0.7, bm25_weight=0.3):
        # Vector search
        vector_results = qdrant_client.search(
            collection_name="textbooks",
            query_vector=embed_query(query),
            limit=20
        )
        
        # BM25 search  
        bm25_results = elasticsearch.search(
            index="textbooks",
            body={"query": {"match": {"text": query}}},
            size=20
        )
        
        # Normalize scores (simplified)
        vector_scores = normalize([r.score for r in vector_results])
        bm25_scores = normalize([r['_score'] for r in bm25_results['hits']['hits']])
        
        # Combine results by document ID
        fused_results = {}
        for i, doc in enumerate(vector_results):
            fused_results[doc.id] = vector_weight * vector_scores[i]
            
        for i, doc in enumerate(bm25_results['hits']['hits']):
            doc_id = doc['_id']
            if doc_id in fused_results:
                fused_results[doc_id] += bm25_weight * bm25_scores[i]
            else:
                fused_results[doc_id] = bm25_weight * bm25_scores[i]
                
        # Return sorted results
        return sorted(fused_results.items(), key=lambda x: x[1], reverse=True)
    ```

## Advanced notes

*   **Reciprocal Rank Fusion (RRF)** is often superior to weighted sum because it doesn't require score normalization and is more robust to different score distributions; it combines rankings based on position rather than absolute scores.
    *   *Example: RRF formula `score = 1 / (60 + rank)` for each result, then summing across both lists, works well when BM25 and vector scores have different scales.*
*   **Adaptive weighting** can dynamically adjust BM25/embedding ratios based on query characteristics, such as giving more weight to BM25 for queries with technical terms or proper names, and more to embeddings for conceptual questions.
    *   *Example: Detect query type using [[RagSystemRoadmap/DominantSubjectFiltering.md]] or term analysis, then adjust weights accordingly before fusion.*
*   **Multi-stage retrieval** uses hybrid search as a first-stage high-recall method, followed by more computationally expensive [[RagSystemRoadmap/OptionallyRerankResults.md|neural reranking]] on the top candidates to achieve optimal precision for the final [[RagSystemRoadmap/ContextConstruction.md]].
